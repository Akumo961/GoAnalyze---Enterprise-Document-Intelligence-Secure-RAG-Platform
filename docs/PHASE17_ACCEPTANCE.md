# Phase 17 — Demonstrable Differentiation Acceptance

**Status:** Implemented acceptance specification  
**Purpose:** Verify that GoAnalyze documents genuine product differentiation without fabricating competitive, customer, regulatory, security, performance, or ROI claims.

## Acceptance criteria

### A. Differentiation is product-specific

The repository must contain a differentiation document covering:

- environmental regulatory workflows;
- evidence traceability;
- government security architecture;
- human-in-the-loop decisions;
- auditability;
- regulatory knowledge architecture;
- deployment flexibility;
- explainable AI;
- measurable workflow value.

### B. Differentiation is evidence-bounded

Every pillar must distinguish repository evidence from evidence that requires a pilot, customer validation, independent assessment, legal review, or other external activity.

### C. Generic-RAG comparison is architectural, not a superiority claim

The documentation must explain the product boundary around generic RAG while explicitly stating that comparative superiority requires a benchmark against named alternatives.

### D. Government decision-support boundary

The documentation must preserve human accountability and must not describe GoAnalyze as an autonomous system for legally binding environmental decisions.

### E. No fabricated claims

The documentation must explicitly avoid unsupported claims about:

- government customers or approvals;
- certifications or compliance;
- ROI or productivity outcomes;
- production readiness;
- competitive superiority.

### F. Evidence hierarchy

The documentation must distinguish automated repository evidence, controlled technical evaluation, pilot evidence, and independent/customer evidence.

### G. Commercial proof plan

The documentation must define a practical proof package covering environmental workflow, retrieval/citations, regulatory knowledge, security, prompt injection, auditability, performance and human-review outcomes.

## Current verification boundary

Phase 17 verifies the **product differentiation framework and evidence discipline** in source control. It does not establish market superiority or customer outcomes.

The following remain external validation items:

- benchmark results against named competing products;
- analyst usability and acceptance studies;
- production customer outcomes;
- independent penetration testing;
- formal certification/accreditation;
- authoritative Québec regulatory-data validation;
- customer-environment deployment acceptance.

## Acceptance result

When the Phase 17 workflow passes, the repository has automated evidence that the differentiation framework exists and respects the project's no-fabrication boundary.
